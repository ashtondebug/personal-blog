# ADR-0010：评论与"点赞"的落地方式（Waline + reaction）

> **用途**：定案评论挂载方式、评论 key 规则，以及"点赞"用什么实现。改评论相关实现前必读。
> **状态**：Confirmed（2026-11-26 用户确认：服务端先留空、点赞用 Waline 自带 reaction）
> **更新**：2026-11-26
> **相关**：[决策索引](./index.md) · [Waline 集成](../integrations/waline.md) · [分析](../integrations/analytics.md) · [ADR-0005](./0005-waline-for-comments.md) · [ADR-0007](./0007-static-dynamic-service-boundary.md)

## 背景

Phase 8 需要落地评论。同时需求里有条件性的"点赞"：只有真正免费且满足要求才启用，否则彻底弃用、不留残留。

服务端部署方式与免费额度尚未验证，用户决定**先把服务端留空**，先完成前端挂载；同时确认**"点赞"用 Waline 自带的 `reaction` 实现**。

## 决策

1. **评论前端先就绪、服务端待定**：服务端地址通过环境变量 `PUBLIC_WALINE_SERVER_URL` 注入；为空时**不渲染评论区、不打包 Waline 客户端**，页面显示一段说明（留言板）或完全不显示（文章页）。
2. **点赞 = Waline `reaction`**，启用（`reaction: true`，最多 9 个表情）。需求中的"免费"由同一套自托管服务承担，不再引入第三方点赞服务。
3. **评论 key 规则**（上线后不可随意改）：
   - 文章：站点 base 前缀之后的完整路径，去尾斜杠，例如 `/zh-CN/blog/hello`；
   - 留言板：固定 `guestbook`，全站共用一块留言板（不按语言拆分）。
4. **不启用 `pageview`**：浏览量是另一条条件性需求，尚未通过免费方案验证（TD-06）；点赞已确认，浏览未确认，两者不捆绑。
5. `dark` 传选择器 `html[data-theme="dark"]`（跟随用户选择的主题，而不是 `'auto'` 跟随系统）；`lang` 走本站映射（日语 `jp`）。

## 备选方案

| 方案 | 为什么没选 |
| --- | --- |
| 先接第三方托管评论（Giscus/Disqus） | 与已确认的 Waline 决策冲突 |
| 点赞另接第三方计数服务 | 多一个外部依赖与隐私面；`reaction` 已能满足 |
| 服务端未定就不做前端 | 会让整个阶段空转；前端与 key 规则可以先行验证 |
| 启用 `pageview` 顺带做浏览量 | 浏览量未通过免费验证，不能搭便车 |

## 选择原因

- **可验证**：用临时环境变量构建即可验证挂载、语言映射、path 与 reaction 参数全部正确（已实测）。
- **零噪声**：未配置时页面不出现"评论加载失败"，也不下载任何评论 JS/CSS。
- **可替换**：服务端选型变化只改一个环境变量。

## 影响

- `@waline/client` 是**客户端依赖**（内部基于 Vue 运行时）：它是第三方预构建组件，不用来写本站 UI，因此不违背 [ADR-0006](./0006-no-default-ui-framework.md) 的"零框架"目标，但需在 [依赖策略](../engineering/dependency-policy.md) 中如实登记体积影响。
- 只有配置了服务端的构建才会把评论 JS/CSS 打进产物；未配置时页面零引用。
- 未配置时 `_astro/` 里仍会留下未被引用的评论 chunk（构建产物+体积，不是运行时开销），登记为 TD-31。
- 服务端一旦上线，`path` 规则立即冻结；改 URL 结构会让评论"错位"。
- 浏览量仍待验证；若最终不可用，不得保留任何占位（与点赞的处理方式一致）。
