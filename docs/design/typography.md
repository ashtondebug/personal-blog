# 字体与排版

> **用途**：定义字体选型策略、中英混排规则与杂志编辑式排版的实现边界。改正文样式、加载字体前必读。
> **状态**：Confirmed（杂志编辑式排版、黑白灰）+ Proposed（字体方案）+ Needs Validation（中文字体体积策略）
> **更新**：2026-11-26
> **相关**：[设计索引](./index.md) · [设计系统](./design-system.md) · [配色与主题](./color-and-theme.md) · [交互准则](./interaction-guidelines.md) · [前端架构](../architecture/frontend-architecture.md)

## 1. 字体族策略（Proposed）

| 用途 | 中文 | 拉丁 | 回退顺序 |
| --- | --- | --- | --- |
| 标题 / 编辑式大标题 | 衬线（宋体系） | 衬线（如 Source Serif 类） | 系统衬线 → `serif` |
| 正文 | 衬线（长文阅读）或中性无衬线（二选一，需定） | 与中文同族风格 | 系统字体栈 |
| UI（导航/按钮/元信息） | 无衬线 | 无衬线 | `system-ui` 优先 |
| 代码 | — | 等宽 | `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` |

原则：**标题有性格、正文字不抢戏、UI 退到背景**。中文与拉丁混排时两族风格要协调（衬线配衬线、无衬线配无衬线）。

## 2. 中文字体体积：本项目最大的排版风险

中文全量字体动辄数 MB 到十几 MB，直接自托管会同时撞上三个约束：GitHub Pages 站点 ≤1 GB、软带宽 100 GB/月、首屏性能。

| 方案 | 优点 | 代价 | 状态 |
| --- | --- | --- | --- |
| A. 系统字体栈（不加载字体文件） | 零体积、零闪动 | 各平台观感不一致，编辑感弱 | Proposal（**默认起点**） |
| B. 自托管子集化字体（按实际用字生成） | 观感统一、体积可控 | 需构建期子集化流程；新增生僻字需重建 | Needs Validation |
| C. 第三方字体 CDN | 接入简单 | 多一个第三方请求与隐私面；可用性不可控 | 不推荐 |
| D. 仅标题用子集化衬线，正文用系统字体 | 兼顾观感与成本 | 标题字形集需覆盖站名与常见标题字 | Proposal（推荐组合） |

**验证清单**（决定 B/D 是否可行）：子集化后单文件大小、`font-display` 策略、首屏是否闪烁、新增内容触发重建的成本、许可证是否允许再分发。

## 3. 字号与行高

数值在 [设计系统 §3](./design-system.md) 定义，本文只给使用规则：

- 正文 `--text-base`，中文行高 1.8、英文 1.7。
- 标题从 `--text-3xl`（文章）到 `--text-4xl`（首页主视觉），跨语言时按语言分别微调（日文假名需要略大行高）。
- 元信息（日期、标签、阅读时间）用 `--text-xs`，灰度降一级，不依赖颜色区分。
- 首字下沉、引文分栏等编辑式手法：**允许用于文章首段**，移动端一律关闭（Proposed，宁少勿多）。

## 4. 行长与留白

- 正文行长：英文 60–75 字符，中文 30–38 字/行。
- 段落间距大于行距一倍以上，才能形成"编辑式"呼吸感。
- 标题与正文之间留白大于正文段落间距，形成层级。
- 图片与正文之间留白 ≥ `--space-8`。

## 5. 中英混排与标点（中文排版的核心细节）

| 场景 | 规则 |
| --- | --- |
| 中文与英文/数字之间 | 加可视间距（可用 CSS `text-spacing` 或手工空格，方案 `Needs Validation`） |
| 中文标点 | 使用全角「，。：；！？」；引号用「」或""，全站统一一种 |
| 英文行内引用 | 用英文标点，不与中文标点混用在同一句 |
| 破折号/省略号 | 中文用「——」「……」 |
| 连续标点 | 禁止「！！」「？？」这类堆叠 |
| 单位与数字 | 数字与单位之间加半角空格（如 `100 GB`） |
| 行首禁则 | 行首不得出现 `，。、；：？！）】」』` 等（CSS 能力有限，`Needs Validation`） |

多语言意味着这些规则要**按语言分别应用**：`en`/`ja` 不需要中文标点规则，`zh-TW` 用繁体标点习惯（如「」保留，但用词不同）。规则集中实现一次，不散落在组件里。

## 6. 多语言排版差异

| 语言 | 差异点 |
| --- | --- |
| `zh-CN` / `zh-TW` | 全角标点；繁简用字不同；不要用简体文案渲染繁体页 |
| `en` | 词间空格断行；标题可全大写但要节制；避免两端对齐造成"河流" |
| `ja` | 假名行高需略增；禁则处理更严格；避免用中文字体渲染假名 |

## 7. 与可访问性

- 正文对比度 ≥ 4.5:1（两种主题都要测），见 [配色与主题](./color-and-theme.md)。
- 不使用纯装饰字体承担正文；标题字体若为装饰性，必须保证字形可辨。
- 允许用户字号放大到 200% 而不破版（`rem` 相对单位，不用 `px` 写死正文）。

## 8. 当前实现（Phase 2）

采用方案 A（系统字体栈），暂不加载任何字体文件：

| Token | 实际取值 |
| --- | --- |
| `--font-serif`（标题与正文） | `'Iowan Old Style', 'Palatino Linotype', 'Songti SC', 'SimSun', 'Noto Serif CJK SC', serif` |
| `--font-sans`（UI/导航/元信息） | `system-ui, -apple-system, 'Segoe UI', 'Noto Sans SC', 'Microsoft YaHei', sans-serif` |
| `--font-mono`（代码） | `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` |

已知代价：各平台观感不一致（macOS 宋体 vs Windows 宋体差异明显）。若日后要统一观感 → 走方案 B/D 子集化，必须先实测体积与首屏（TD-10 仍开放）。
