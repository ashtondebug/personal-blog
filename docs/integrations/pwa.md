# PWA 集成

> **用途**：可安装与离线能力的边界、缓存策略与更新机制。改 Service Worker 前必读。
> **状态**：Confirmed（需要基础 PWA）+ Proposed（实现方案）+ Needs Validation（缓存与更新冲突）
> **更新**：2026-11-26
> **相关**：[集成索引](./index.md) · [部署架构](../architecture/deployment-architecture.md) · [搜索](./search.md) · [Web 标准参考](../references/web-standards.md) · [技术债](../../plans/tech-debt.md)

## 1. 目标与不做的事

**要**：可安装（有图标、名称、主题色）；已访问过的页面在断网时可打开；打开速度略快。

**不要**：不做"离线编辑"、不做后台同步、不缓存评论请求、不做推送通知、不做复杂预缓存策略。

## 2. Manifest

由 HTML `<link rel="manifest">` 引用，成员（标准层面稳定，MDN 核验 2026-11-26）：

| 成员 | 取值 | 风险 |
| --- | --- | --- |
| `name` | 站点全名 | 站点名未定 → 走配置项，禁止写死 |
| `short_name` | 简称（≤12 字符） | 同上 |
| `start_url` | 应由基路径生成（`/<repo>/`） | 手写会在 `base` 变更后失效 |
| `display` | `standalone` | — |
| `theme_color` / `background_color` | 取自灰阶 token | 需与深色模式协调（仅支持单一 theme_color） |
| `icons` | 至少 192 与 512 两种尺寸，maskable 可选 | 路径必须带 `base` |

`theme_color` 只能取一个值，深浅主题下安装后的标题栏颜色会不一致——这是标准限制，接受即可，不为此自造方案。

## 3. Service Worker

- 仅在生产构建中注册；本地开发不注册，避免调试被缓存干扰。
- 要求安全上下文（HTTPS 或 localhost），GitHub Pages 默认 HTTPS 满足。
- **必须**：内容更新后用户能看到新内容。这是本特性的最大风险（SW 是唯一能"自己决定缓存"的地方）。

### 3.1 缓存策略取舍

| 内容 | 策略 | 理由 |
| --- | --- | --- |
| HTML 页面 | 网络优先，失败回退缓存 | 保证内容新鲜，断网仍可读 |
| 带哈希的静态资源（CSS/JS/字体） | 缓存优先 | 内容变则 URL 变 |
| 图片 | 缓存优先 + 上限淘汰 | 体积大，影响弱网体验 |
| 搜索索引 | 缓存优先，构建版本变化时失效 | 索引随构建更新 |
| 评论接口 / 浏览量接口 | **不缓存** | 强时效，缓存会产生"看不到新评论"的假故障 |

### 3.2 更新机制

- 新 SW 安装完成后不立刻接管，提示用户"有新版本"或在下一次导航时更新。
- 每次构建生成版本号（如内容哈希或构建时间），写入缓存名，旧缓存清理。
- 发布后必须人工验证：刷新能看到新文章（见 [测试策略](../engineering/testing-strategy.md)）。

## 4. 与 `base` 的关系

站点发布在 `/<repo>/` 下，`start_url`、`scope`、图标路径、SW 作用域都受其影响。所有路径必须由构建配置生成，**禁止手写绝对路径**（[部署架构](../architecture/deployment-architecture.md)）。

自定义域名迁移后（`base` 被移除），旧 SW 可能仍在旧作用域下生效 → 迁移时需考虑让旧 SW 自注销（`Needs Validation`）。

## 5. 验证清单

- [ ] 安装提示可用，图标与名称正确，启动后进入正确语言首页。
- [ ] 断网可打开首页与一篇已访问过的文章。
- [ ] 重新发布后，普通刷新能拿到新内容（不是陈旧页面）。
- [ ] 评论区不因 SW 而显示过期内容。
- [ ] Lighthouse 的 PWA 相关检查项无硬性失败（阈值 `Needs Validation`）。
- [ ] `start_url`、图标与 SW 均能在 `base` 前缀下正常访问。
