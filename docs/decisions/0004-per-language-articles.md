# ADR-0004：采用独立语言文章策略

> **用途**：定义多语言内容的策略边界。任何"加自动翻译/加语言回退/改语言切换"的提议先读本文。
> **状态**：Confirmed（用户明确要求）
> **更新**：2026-11-26
> **相关**：[决策索引](./index.md) · [路由与 i18n](../architecture/routing-and-i18n.md) · [信息架构](../product/information-architecture.md) · [需求 REQ-I18N](../product/requirements.md)

## 背景

站点支持 `zh-CN`、`zh-TW`、`en`、`ja` 四种语言，但作者不可能为每篇文章提供四种语言的版本。若采用"翻译缺失即回退"的常见方案，读者会在英文页面读到中文正文，产生"这里有翻译"的错觉；回退还会让 `hreflang` 与 SEO 语义失真。

## 决策

1. **一篇文章只属于一种语言**，语言由所在目录决定，不在 frontmatter 重复声明。
2. **不强制翻译，不自动机翻，不回退渲染**。
3. 只有当同一内容存在多个语言版本（通过 `translationKey` 关联）时，才在语言切换器中互相链接。
4. 站点级页面（首页、列表、About、Guestbook 等）**四种语言始终完整存在**，文案来自完整词典；内容页按实际存在的语言生成。
5. 不为不存在的语言版本生成任何链接、`hreflang` 或导航项。

## 备选方案

| 方案 | 为什么没选 |
| --- | --- |
| 单一默认语言 + 回退渲染（常见 i18n 默认行为） | 读者看到错误语言的内容，等于伪造翻译 |
| 强制每篇翻译（工作量为 4 倍） | 不可持续，最终会变成占位翻译 |
| 自动机器翻译 | 用户明确禁止；质量与责任都无法接受 |
| 只做中英双语 | 违背已确认的四语言需求 |

## 选择原因

- **诚实**：没有的版本就是不显示，读者不会被误导。
- **可维护**：每篇文章只需维护一份，作者按需补翻译。
- **SEO 干净**：不存在同一 URL 的"语言窃取"，`hreflang` 只指向真实存在的页面。
- **实现更简单**：无需在路由层做 fallback 分支，构建期可静态枚举。

## 影响

- 语言切换器必须**按页面类型区分行为**（站点级：始终可切；内容页：仅在有版本时可切），这是 UI 复杂度所在（[交互准则](../design/interaction-guidelines.md)）。
- Waline 评论按语言 path 天然隔离：同一条目不同语言版本的评论互不相通（可接受，且符合预期）。
- 搜索默认只检索当前语言（[搜索集成](../integrations/search.md)），跨语言检索属于额外功能，未确认。
- `translationKey` 必须人工保持一致；写错会导致语言切换指向错误页面 → 需在构建期做一致性校验（同一 key 下 `locale` 不得重复）。
