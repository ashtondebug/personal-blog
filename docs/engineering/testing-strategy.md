# 测试策略

> **用途**：定义"什么算通过"。每个阶段结束、每次发布前按本文验收。
> **状态**：Proposed（策略）+ Needs Validation（工具与阈值）
> **更新**：2026-11-26
> **相关**：[工程索引](./index.md) · [构建与部署](./build-and-deployment.md) · [路线图](../../plans/active/000-initial-implementation-roadmap.md) · [交互准则](../design/interaction-guidelines.md) · [文档一致性工具](../../scripts/check-docs.mjs)

## 1. 分层：从便宜的检查开始

| 层 | 检查什么 | 何时跑 | 失败意味着 |
| --- | --- | --- | --- |
| L1 类型与 schema | TS 类型、frontmatter zod 校验 | 每次提交 / 构建 | 内容或代码契约被破坏 |
| L2 构建 | `astro build` 成功、无警告性错误 | 每次提交 / 推送 | 站点无法发布 |
| L3 链接与结构 | 文档相对链接、站内链接、资源路径存在 | 每次提交（文档）+ 发布前（站点） | 用户会遇到 404 |
| L3.5 安全基线 | 外链 `rel`、混合内容、内联事件、第三方脚本、manifest/sw | CI 构建后 | 安全回归 |
| L4 冒烟 | 首页/文章/搜索/评论四条路径可打开 | 每次发布后 | 发布失败或外部服务故障 |
| L5 人工体验 | 键盘流程、对比度、深浅色、移动端 | 每阶段结束 | 可用性缺陷 |
| L6 性能 | Lighthouse 或等价的实测指标 | 关键阶段 | 性能回退 |

优先把 L1–L3 自动化，L5/L6 用清单人工执行（引入重型 E2E 需先论证，见 §5）。

## 2. 各层具体做法

### L1 类型与 schema

- Content Collections 的 zod schema 是内容质量的主防线：必填缺失、类型错误、非法枚举都应让构建失败（[数据模型](../architecture/data-models.md)）。
- 额外构建期校验（写在集成或脚本中）：`translationKey` 同组语言不重复；分类与标签非空；`draft` 内容不进产物。

### L2 构建

- 构建必须"干净可复现"：相同输入两次构建产物一致（时间戳类字段需固定）。
- 构建日志中的告警（弃用 API、缺失资源）视为待办，登记 [技术债](../../plans/tech-debt.md)。

### L3 链接检查

- **文档**：`node scripts/check-docs.mjs`（已存在）检查 Markdown 相对链接与必需的文档头字段。
- **站点**：发布前对产物做一次内部链接检查（工具选型 `Needs Validation`，候选：构建期脚本扫描 `href`/`src`）。
- 重点覆盖：语言切换链接、分类/标签聚合链接、图片与音频路径（`base` 前缀最容易错）。

### L4 发布后冒烟（每次发布都做）

- [ ] 首页在某语言下正常渲染，样式加载成功。
- [ ] 任一文章页正文、目录、代码块、图片正常。
- [ ] 搜索能返回结果（索引已生成）。
- [ ] 评论区可加载（外部服务可用）。
- [ ] 语言切换落到正确页面，无翻译的文章不显示错误链接。
- [ ] 断网/服务不可用时的降级文案出现（可用开发者工具模拟）。

### L5 人工体验清单

- 键盘完成：`/` 搜索 → `Esc` 关闭；灯箱 `←/→` 翻页；Tab 遍历导航。
- 焦点可见（两种主题）、触控目标 ≥ 44px。
- 浅色/深色下对比度实测达标（[配色与主题 §6](../design/color-and-theme.md)）。
- 移动端无横向滚动、悬浮播放器不遮挡内容。
- `prefers-reduced-motion` 下无位移动画。

### L6 性能

- 记录指标：LCP、CLS、首屏 JS 体积、搜索索引体积。
- 阈值待定（`Needs Validation`）：需先有站点实测数据再定，禁止凭感觉设 KPI。

## 3. 内容变更的专项检查

新增/修改内容后额外确认：schema 通过、语言目录正确、`translationKey` 一致、图片 `alt` 与宽高齐备、EXIF 无 GPS（[媒体存储](../integrations/media-storage.md)）、分类/标签已存在于词表或按规则新增。

## 4. 失败的处置

- L1/L2 失败：**阻断提交**，修到通过为止。
- L3 失败：阻断发布；文档链接失败可本地修复后重跑。
- L4 失败：回滚或立即修复，不允许"先放着"。
- 无法立即修复的问题 → 登记 [技术债](../../plans/tech-debt.md)，写明影响与临时降级。

## 5. 不做什么（避免过度工程）

- 不引入浏览器 E2E 框架（Playwright 之类），除非交互复杂度显著上升——引入需 ADR。
- 不为纯静态文本页写单元测试（类型与构建已覆盖）。
- 不追求覆盖率数字；追求"关键路径有检查"。
