# 隐私规范

> **用途**：什么是绝对不能出现在站点上的信息，以及发布内容前的自查清单。发布任何内容或图片前必读。
> **状态**：Confirmed（硬规则来自用户要求）+ Proposed（具体措施）
> **更新**：2026-11-26
> **相关**：[安全索引](./index.md) · [安全基线](./security-baseline.md) · [媒体存储](../integrations/media-storage.md) · [Waline](../integrations/waline.md) · [需求 §9](../product/requirements.md)

## 1. 绝对禁止出现在站点上的内容

| 类别 | 具体项 |
| --- | --- |
| 身份 | 真实姓名、学校、班级、学号、身份证件信息 |
| 位置 | 住址、精确 GPS 坐标、可推断住址的日常生活轨迹 |
| 联系方式 | 私人手机号、私人邮箱、即时通讯账号（除非作者明确决定公开） |
| 账号凭据 | 任何 API key、token、数据库连接串、私有仓库地址中的凭证 |
| 他人信息 | 未经同意的第三方姓名、照片、联系方式 |

**不编造**：没有提供的个人信息一律不写。About 页宁可简短，也不能由 Agent 编造经历、学历、职位。

## 2. 图片与 EXIF

照片的元信息是常见的隐私泄漏渠道：

- 入库前剥离 EXIF（尤其是 GPS、设备序列号、拍摄时间精度）。
- 首页/Gallery 展示的"拍摄地点"由作者决定粒度（城市级安全，街道级危险）。
- 人像照片需有被摄者同意；无法确认时用背影、局部或删去。

## 3. 内容层面的间接泄漏

- 截图中的路径、用户名、授权码、书签栏、聊天窗口。
- 代码示例里的真实域名、内网 IP、个人邮箱。
- 日志、构建输出、错误信息里夹带的本地绝对路径与用户名（`D:\Dev\...`、`C:\Users\<name>\...`）。
- 文档里粘贴的真实数据库地址与口令。

## 4. 评论系统的数据

Waline 会保存访客填写的昵称、邮箱（可选）、网址与 IP 等用于反垃圾的信息。要求：

- 在评论入口附近或在 About/隐私说明处告知"评论数据由 Waline 服务存储"（是否需要独立隐私页 `Needs Validation`）。
- 不在前端页面暴露管理端地址与管理凭据。
- 管理账号启用强密码，不与代码仓库共用凭据。
- 提供删除评论的能力（后台可删），并明确作者为数据控制者。

## 5. 第三方请求

- 每新增一个第三方请求都要能回答："它知道访客的哪些信息？"答不清就不加。
- 不使用跨站追踪、不埋设指纹脚本、不加载广告/社交像素。
- 字体与图标优先本地或系统能力，避免为排版引入第三方域名（[排版](../design/typography.md)）。

## 6. Cookie 与本地存储

- 允许：主题、列表视图、语言偏好等**功能性**本地存储（`blog:` 前缀）。
- 不允许：任何追踪标识、跨站标识、长期行为画像。
- 若 Waline 设置了 cookie，其用途应在隐私说明中列出（`Needs Validation`：以 Waline 官方行为为准）。

## 7. 发布前检查清单

- [ ] 全文搜索真实姓名/学校/班级/手机号/私人邮箱 → 无。
- [ ] 图片已剥离 EXIF，无 GPS。
- [ ] 截图无用户名、路径、令牌、书签。
- [ ] 代码示例无真实凭据与内网地址。
- [ ] 文档与构建日志不含本机绝对路径（用相对路径）。
- [ ] About 页没有编造内容。
- [ ] 新增第三方请求已评估并记录。
- [ ] 评论区隐私告知到位。
