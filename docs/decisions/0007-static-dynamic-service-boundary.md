# ADR-0007：静态能力与外部动态服务的边界

> **用途**：定义"什么能做在 Pages 上、什么必须外置"。任何新增功能必须先按本文分类。这是本项目最重要的一条架构界线。
> **状态**：Confirmed（架构约束）+ Needs Validation（各外部服务的具体选型）
> **更新**：2026-11-26
> **相关**：[决策索引](./index.md) · [系统总览](../architecture/system-overview.md) · [部署架构](../architecture/deployment-architecture.md) · [ADR-0002](./0002-github-pages-hosting.md) · [ADR-0005](./0005-waline-for-comments.md)

## 背景

GitHub Pages 只返回静态文件，没有运行时、没有数据库、不能执行服务端逻辑。而博客又需要评论（写入 + 跨用户持久化）以及可选的浏览量统计（服务端计数）。把这两类需求混进静态构建，会导致要么功能不可实现，要么用假数据糊弄（需求明确禁止）。

## 决策

把全部功能分为三类，**新增功能必须先归类，归类失败说明方案不可行**：

| 类别 | 判据 | 允许的技术 | 例子 |
| --- | --- | --- | --- |
| A. 构建期能力 | 输入是仓库内的文件/配置，输出是静态文件 | Node 构建脚本、Astro 集成、Markdown 插件 | 内容聚合、标签索引、阅读时间、热力图、TOC、搜索索引、反向链接 |
| B. 浏览器能力 | 只需读写当前用户的本地状态，或读取已发布的静态文件 | 原生 ES Module、DOM、localStorage、Fetch 静态资源 | 主题三态、搜索查询、灯箱、阅读进度、播放器、快捷键 |
| C. 外部服务能力 | 需要写入并跨用户持久化，或需要服务端聚合计数 | 独立部署的服务（Waline 及其数据库） | 评论、Guestbook、可选浏览量、可选反应(点赞) |

硬规则：

1. **A 类的产物不能依赖网络**（构建可重复、可离线）。
2. **B 类不得引入写入型后端**；B 类的能力在 JS 失败时必须降级为可用。
3. **C 类必须是可替换的独立服务**：站点只通过公开 HTTP 接口连接，服务下线不导致页面不可读。
4. 任何"看起来需要后端"的需求，先问：能否退化为 A 或 B？不能才进入 C，并补 ADR + 集成文档。

## 备选方案

| 方案 | 为什么没选 |
| --- | --- |
| 换用支持 SSR 的托管（Vercel/Node 适配器） | 违背"GitHub Pages 静态托管"的已确认决策 |
| 用第三方 SaaS 承担一切动态能力 | 违反依赖最小化与隐私原则；免费额度不可控 |
| 用静态文件 + PR 提交当"评论" | 体验不可接受（需登录 GitHub、非实时） |

## 选择原因

- **部署形态决定能力上限**：静态托管下，把动态需求硬塞进来只会产生伪功能。
- **故障隔离**：评论服务挂了，文章照样能读。
- **判断可复用**：后来者只要看这张表就知道自己的方案归哪类。

## 影响

- 浏览量（REQ-DATA-03）与点赞（REQ-DATA-05）属于 **C 类条件性功能**：无法验证免费方案时，**整体不实现**，且不得留下按钮/UI/接口/数据结构/占位。
- 搜索不能走服务端 → 必须是构建期索引 + 浏览器查询（[搜索集成](../integrations/search.md)）。
- 双向链接、关联推荐必须是构建期计算（[内容架构](../architecture/content-architecture.md)）。
- 每个 C 类服务都需要：降级文案、隐私说明、免费额度与停服风险评估、数据导出方案（[Waline 集成](../integrations/waline.md)）。
